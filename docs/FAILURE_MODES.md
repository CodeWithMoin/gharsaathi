# Failure modes

What GharSaathi does when something breaks: a store, OpenAI, the browser, the
network or the backend itself. Each row says what triggers it, where the code
notices, what the user must **see**, what the assistant must **say** (one line, in
the profile's language; Hinglish shown), what must **never** happen, how the user
recovers, and which tests pin it.

Run only these tests with `make test-failures` (see [TESTING.md](TESTING.md#failure-mode-tests)).

## Rules that hold for every row

1. **An error is never "not found".** A store that could not be reached, timed out,
   rate-limited us or sent an unreadable answer says nothing about whether the product
   exists. Tool status `provider_error` (with a `reason`) or `error`, UI event
   `tool.error`, never an empty results card.
2. **Never claim placed or paid without the provider.** Only a provider-confirmed order
   id is "placed"; only a provider-confirmed payment is "paid". Every uncertain state
   (`outcome_unknown`, `payment_unknown`, `payment_succeeded`, …) is shown and spoken as
   *not confirmed*.
3. **Never retry an order or payment call.** One `create_*` call per approval (durable
   claim); payment status is single `check_payment_status` reads. Only read-only Zepto
   tools are retried, once, after a session reset.
4. **Never change the basket unprompted.** A failed bill, an out-of-stock item or a price
   change is reported; the user decides what to remove or change.
5. **No secrets.** No PIN/OTP/CVV/card number is ever asked for; logs and errors carry no
   provider text, tokens or API keys.

## Status

`covered` = an offline test asserts the row · `xfail` = a strict `xfail` test pins the
expected behaviour that main does not have yet (the reason names the row and the branch) ·
`manual` = the behaviour lives in a React component or a real device and is checked by the
owner (MVP checklist) · `gap` = known wrong today, not testable offline.

Test references: `tests/…` are backend pytest node ids (a prefix selects every test that
starts with it), `frontend:FM-…` is a test in `frontend/tests/unit/failure-modes.test.mjs`,
`delegation:…` is a scenario in `backend/evaluation/failure_scenarios.json` (real backend
model, run twice, both passed on prompt 1.23.0).
